# Round 1 Changelog: Unified Agent Hooks

## Plan

- Plan: `plan-unify-agent-hooks-2026-07-11.md`
- Date: 2026-07-11
- Status: implementation complete; manual Codex trust/UI observation remains

## Outcome

Workspace-meta now manages one shared SessionStart status policy for Claude Code
and Codex. The current host has been migrated from multiple legacy groups to one
handler per agent without replacing unrelated host configuration.

The direction-setting hook-output question is resolved: current official Codex
hooks documentation explicitly defines `systemMessage` as a UI/event-stream
warning and plain SessionStart stdout as extra developer context. The Codex
0.144.1 implementation matches that contract.

## Changed Artifacts

- Added repository-local `AGENTS.md` with plan, verification, ownership, and
  commit-authorization rules.
- Added `scripts/workspace_status.py`, the ordered status evaluator shared by
  Claude and Codex.
- Reworked `scripts/sync_codex_config.py` to render and validate Codex AGENTS,
  Codex TOML, and Claude JSON before writing any target.
- Replaced three Codex handlers with one hash-pinned handler template in
  `.agents/host-templates/codex-hooks.toml`.
- Migrated Claude from marker-only additive installation to one convergent,
  wholly owned SessionStart group.
- Added offline fetch throttling and warning TTL through host-local cache state.
- Added `make agent-sync-check` for read-only drift detection.
- Added architecture/operator documentation and updated README/W-R28 ownership
  language.
- Added 19 regression tests covering status semantics, migration, preservation,
  invalid input, hash mismatch, and idempotency.
