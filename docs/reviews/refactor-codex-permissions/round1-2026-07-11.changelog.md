## Outcome

Codex now has a two-layer permission policy:

- The workspace-meta managed AGENTS block pre-authorizes native web search, URL
  retrieval, read-only remote queries, and ordinary inspection without a
  conversational confirmation step.
- The current host has a separate
  `~/.codex/rules/permissions.rules` drop-in containing executable allow/prompt
  decisions. The file is host-local and is not tracked by workspace-meta.

## Routine / Read Policy

The local policy explicitly allows only bounded operations such as:

- bounded local inspection with `cat`, `jq`, `ps`, and related tools;
- bounded local Git status/ref/path inspection;
- high-level read-only GitHub queries such as `gh pr view`, `gh run view`, and
  `gh search`.

Native web search and URL retrieval use the native tools rather than shell
network clients. Routine sandbox-contained commands such as `rg`, `sed`,
workspace-local `cp`, Git diff/log/show, `python3 -c`, and
`codex execpolicy check` remain unmatched so the active sandbox evaluates their
actual targets without a false-positive executable-level prompt.

## Prompt Policy

The local policy prompts for representative material mutations, including:

- Git commit, push, merge, pull, rebase, reset, clean, switch, restore, tag,
  apply, and related content/history/ref changes;
- GitHub API writes, PR merge, repository/release/secret/variable/workflow
  mutations;
- shell network clients, SSH/data transfer, privilege elevation, system
  package/service changes, container/cluster controls, deployment, and
  destructive file/process/device operations;
- Codex nested-agent/session/service entry points and user-level auth,
  MCP/plugin/feature mutations.

Hook-trust and approval/sandbox bypass commands are forbidden.

Codex applies the most restrictive matching rule. Verification confirmed that
new prompt rules override older `default.rules` allow entries for `git commit`,
`git push`, `ssh`, `systemctl`, Docker Compose mutations, and other covered
operations.

  after the final edit.

## Limitations

- Execpolicy matches argument prefixes, not arbitrary semantic intent. Shell
  network clients therefore remain prompt rather than attempting to infer
  method/flags; native Web Search is preferred for retrieval.
- Native Web Search is not an execpolicy command. Its no-confirmation behavior
  is expressed in managed guidance, not in `.rules` syntax.
- The `rules/` directory is the drop-in mechanism: Codex loads every `.rules`
  file together and uses the most restrictive matching decision. The filename
  does not create override order or precedence.
- The policy does not disable the sandbox or grant danger-full-access.
- The host-local rule is intentionally not committed or pushed.
