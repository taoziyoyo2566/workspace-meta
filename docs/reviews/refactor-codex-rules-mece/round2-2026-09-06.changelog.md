# Round 2 — Keep One-Time Git Transactions Out Of Project Content

## Plan

[Stop Persisting One-Time Git Transactions As Project Content](plan-stop-persisting-git-transactions-2026-09-06.md)

## Outcome

The shared branch rule now treats branch creation and switching as a
proportional, reviewed Git transaction. It no longer requires every branch to
carry a permanent lifecycle contract or requires that contract to become the
first repository write and first implementation publication.

A durable workstream contract first requires a project-declared canonical
carrier/schema and additionally requires either an explicit project contract
rule or observable cross-session/cross-agent handoff need. Branch-only requests
preserve the reviewed content diff except for cleanup the user explicitly
authorized. Git refs and reviewed commits carry durable action evidence;
worktree state and reflogs remain local diagnostics.
