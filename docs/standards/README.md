# 工程规范使用手册

这套资料帮助人和 AI 协作者把项目从问题、设计推进到开发、验证和交付。适用于小团队的软件与运维项目，具体技术、命令和验收数值由各项目确定。

它依据社区实践整理，是本工作区的工程约定，不宣称符合某项认证标准。[来源与取舍](sources.md)区分了外部依据和本地选择。

## 从哪里开始

| 现在要做什么 | 阅读入口 | 应得到什么 |
|---|---|---|
| 讨论新功能、架构或较大的改动 | [设计规范](design.md) | 看得懂的方案：改什么、为什么、怎样验收 |
| 编码、改配置、修缺陷、做评审 | [开发与评审规范](development.md) | 范围清楚、可维护、有行为证据的变更 |
| 把方案拆成任务、实施、上线或交接 | [实施与交付规范](delivery.md) | 有顺序、前置条件、完成标准的具体任务 |
| 需要写法示例 | [简短模板](templates.md) | 按需复制相关部分，删掉无关字段 |

## 工作量决定文档量

| 改动情形 | 通常足够的做法 |
|---|---|
| 文案、格式、明确的小修复 | 直接修改，做相关检查，说明结果 |
| 行为变化或跨模块改动 | 在现有任务或方案中写清行为、接口、取舍和验收 |
| 架构、安全边界、数据迁移、多阶段实施 | 使用项目的持久化方案，补必要的风险、阶段和恢复安排 |
| 生产操作、需要跨人或跨会话接续 | 使用项目操作手册；按需要保存实际操作结果 |

一个任务不需要同时建立设计文档、Plan、ADR、任务清单和操作日志。先找现有载体；只有读者任务或生命周期确实不同时才拆文件。小改动不因使用模板而升级成复杂流程。

## 规范放在哪里

本手册是共享规则的中文说明和使用示例，不是第二套独立维护的强制规则。自动化协作者仍按入口加载下列规则；手册与规则出现差异时，应修正手册，不能据此绕过规则。

| 内容 | 唯一规则来源 |
|---|---|
| 方案范围、设计表达、阶段与验收 | [planning.md](../../.agents/rules/planning.md) |
| 模块职责、代码与数据、依赖和变更范围 | [implementation.md](../../.agents/rules/implementation.md) |
| 验证选择、行为证据、发布物与检查结果 | [verification.md](../../.agents/rules/verification.md) |
| 评审发现、严重性与停止条件 | [review.md](../../.agents/rules/review.md) |
| 文档归属、任务与操作记录 | [documentation.md](../../.agents/rules/documentation.md) |
| 授权、Git、敏感信息与环境事实 | [authorization.md](../../.agents/rules/authorization.md)、[git.md](../../.agents/rules/git.md)、[secrets.md](../../.agents/rules/secrets.md)、[environment-truth.md](../../.agents/rules/environment-truth.md) |

workspace-meta 保存跨项目方法；项目仓库保存自己的架构、方案、任务、操作命令和结果。采用本手册不需要把它复制进每个项目，也不会自动批准已有草案、部署或 Git 发布。
