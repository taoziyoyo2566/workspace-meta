# Agent Configuration Ownership

Workspace-meta manages a deliberately small, reviewable subset of Claude Code
and Codex user configuration. It does not mirror either home directory.

| Surface | Ownership | Sync behavior |
|---|---|---|
| `~/.codex/AGENTS.md` | mixed | workspace-meta replaces only its marked block; other text is preserved |
| `~/.codex/config.toml` | mixed | workspace-meta replaces only its marked hook block; other settings are preserved |
| `~/.claude/settings.json` | mixed | workspace-meta converges one dedicated SessionStart group; other settings and groups are preserved |
| `scripts/workspace_status.py` | workspace-meta | one ordered status policy is shared by both agents |
| model/reasoning defaults | host/user | remain in `~/.codex/config.toml` |
| project trust and hook trust hashes | host | never copied or generated by this repo |
| `~/.codex/rules/default.rules` | host authorization history | never sync; audit locally and never embed secrets in approvals |
| `~/.codex/rules/permissions.rules` | host permission drop-in | never sync; Codex loads it together with `default.rules` and uses the stricter matching result |
| `auth.json`, history, SQLite state, logs, caches | private runtime state | never sync |
| system skills and remote plugin caches | Codex-managed | never sync |
| project `AGENTS.md`, `.agents/`, `.codex/` | project repo | travel with that project's own repository |

## Why narrow managed surfaces

Codex reads one global `AGENTS.md` from `CODEX_HOME` and combines it with
project-local guidance. A full-file copy would erase host-local preferences, while
an append-only installer would leave stale rules and hooks forever. Marked blocks
provide explicit ownership: workspace-meta converges what it owns and preserves
everything else. Claude has no equivalent marked TOML surface, so the same rule
is represented as one wholly owned SessionStart group in its JSON settings.

`scripts/sync_codex_config.py` performs atomic writes. It validates the resulting
TOML and JSON before replacing any target, migrates legacy workspace-meta hooks,
and refuses ambiguous mixed hook groups rather than deleting user hooks. The
installed command pins the SHA-256 of `scripts/workspace_status.py`; an evaluator
change therefore becomes a visible hook-command change. Codex hooks must then be
reviewed again with `/hooks`, because trust is bound to the command hash.

The evaluator emits no output when healthy and otherwise emits exactly one JSON
`systemMessage`. Remote fetches have a short minimum interval and remote-failure
warnings have a host-local TTL in `~/.cache/workspace-meta/status.json`; dirty,
ahead, behind, and stale-registry warnings are not suppressed. The synchronizer
requires Python 3.11+ (`tomllib`); bootstrap skips it with a clear warning when
that prerequisite is unavailable.

`AGENTS.override.md` has higher global precedence than `AGENTS.md`. Bootstrap warns
when a non-empty override exists because the synchronized base guidance will then
be inactive by Codex design.

See `docs/architecture/codex-config-management.md` for the full lifecycle,
migration rules, operator commands, and troubleshooting guide.
