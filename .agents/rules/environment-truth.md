# Environment Truth

Agent-neutral workspace rule for load-bearing capability and environment facts.

## Ownership

This file owns freshness, probe, registry, and blocked-verdict semantics.
Projects own task-to-command mapping and project environments. Agent adapters
own their concrete capability tools.

## Dated Snapshots

Environment and remote capability facts are dated snapshots, not invariants.
Before a claim becomes a plan prerequisite, delegated operator step, blocked
verdict, or skipped check, re-probe it with the cheapest sufficient method.

A “cannot run here” verdict cites current probe/registry evidence. Bare-host
absence does not prove a project venv, container, Makefile, or adapter cannot
run the check.

Memory, prior plans/changelogs, and earlier user statements all age; none alone
supports a current environment verdict.

## Contradiction

When a probe contradicts a living record:

1. update the record promptly with probe date, or name the exact deferred
   owner/gap;
2. report when the correction is local-only or unpublished;
3. never require an automatic same-round commit/push;
4. never write “assume this, do not re-discover” for an aging fact.

Publication follows `git-publication.md`.

## Per-Host Registry

Probe results live in `.agents/env/<hostname -s>.yml` at the workspace root,
generated by `scripts/env_probe.sh` / `make env-probe`; never hand-edit them.
The registry contains host capability facts and host-conditional hints, not
project task mapping or credentials.

Consult the registry before ad hoc probes. Refresh when
`make env-probe-check` reports missing/stale. TTL is a floor: an observed
command/daemon/network failure invalidates the relevant entry immediately.

Bootstrap or task execution runs/refreshes the probe only when a capability
claim is load-bearing. A background SessionStart drift signal may warn about
staleness but does not force every quick session to load this module.
