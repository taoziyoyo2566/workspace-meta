# Environment Truth

Workspace-wide rule (elaborates workspace `CLAUDE.md` W-R24). Use this before
relying on any recorded claim about the execution environment (tool
installed/absent, daemon running, credentials present, service reachable).

## Core rule

Environment capability facts are **dated snapshots, not invariants**. They expire
silently when something is installed, removed, or reconfigured between sessions.

- Before an environment claim becomes **load-bearing** — a plan pre-condition, a
  delegation-to-operator model, a "blocked" verdict, a skipped verification gate —
  **re-probe it**. Probes are cheap (< 5 s):
  - `command -v <tool>` / `<tool> --version`
  - `docker version` / `docker ps`
  - `gh auth status` / `git ls-remote origin HEAD`
- A "cannot run here" verdict must cite a **fresh probe**, never a recollection.

## Sources that age

All of these carry an implicit date and must not be trusted without re-probing:

- agent memory files and session summaries
- prior round changelogs and plan pre-condition sections
- **user statements** ("X isn't installed yet") — true when said, not forever

## Same-round correction

When a probe contradicts a recorded fact:

1. Update the record (memory file / doc / plan pre-conditions) in the **same round**.
2. Stamp the fact with the probe date.
3. Never write "assume this, don't re-discover" environment claims — that wording
   is the anti-pattern that caused the 2026-06-10 incident (a "no Docker daemon"
   memory outlived the limitation and mis-shaped an [L2] plan's delegation model).

## Per-host capability registry

Probe results persist in `.agents/env/<hostname -s>.yml` at the **workspace root**
(committed to the workspace-meta repo; one file per machine; generated by
`scripts/env_probe.sh` / `make env-probe` — never hand-edit). One shared registry
serves every project under `~/workspace`.

- **Consult the registry first** instead of re-deriving probes ad hoc; refresh it
  when `make env-probe-check` reports missing/stale (TTL 7d) — first session on a
  new machine must run `make env-probe` before relying on any recorded claim.
- TTL is a floor, not a guarantee: any mid-session `command not found` / daemon
  error on a listed capability invalidates the entry immediately — re-probe and
  commit the updated registry in the same round.
- "Blocked" verdicts in changelogs cite the registry entry (host + probed_at) as
  probe evidence.
- The registry carries **host capability facts + host-conditional hints only**.
  A project's task→command mapping is that project's own SSOT (e.g. its testing /
  governance docs) — link to it, never copy it here.

## Session-bootstrap hook

During session bootstrap for substantial work, run `make env-probe-check`; if it
fails, run `make env-probe` (Claude: `/env-sync` skill, installed per-host under
`~/.claude/skills/`) before the task plan leans on any environment capability.
